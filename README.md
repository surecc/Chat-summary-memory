# 群忆 · 微信群聊总结与回忆小程序 — 产品方案

> 一个能总结微信群聊上下文、整理群内图片、并基于图片语义 + 聊天语境生成"珍贵回忆小结"的产品。

## 快速开始（本仓库结构）

```
├── project.config.json        # 微信开发者工具项目配置
├── miniprogram/               # 小程序前端（原生）
│   ├── app.js / app.json / app.wxss
│   └── pages/
│       ├── index/             # 首页：上传群聊截图、发起解析
│       ├── summary/           # 总结结果：话题 / 待办 / 金句
│       ├── album/             # 群相册：照片提取与事件聚类（占位）
│       └── memory/            # 珍贵回忆：周卡片 / 月记忆册 / 年报告（占位）
└── cloudfunctions/
    └── summarize/             # 云函数：截图 → 多模态大模型 → 结构化总结
```

使用步骤：
1. 用**微信开发者工具**导入本仓库根目录（AppID 可先用测试号）
2. 开通**云开发**，把 `miniprogram/app.js` 里的 `YOUR_CLOUD_ENV_ID` 替换为你的环境 ID
3. 在云函数 `summarize` 的环境变量里配置 `ANTHROPIC_API_KEY`，右键上传并部署（云端安装依赖）
4. 真机预览：上传几张群聊截图 → 生成总结

## 0. 先讲清楚一个硬约束

**微信小程序（以及公众号）没有任何官方 API 可以读取微信群聊天记录。**
微信不向第三方开放群消息。因此本产品的形态设计核心，不在于"怎么总结"，而在于**聊天数据如何合规地进入系统**。所有形态都是围绕这个约束展开的。

## 1. 可行产品形态对比

| 形态 | 数据获取方式 | 合规性 | 用户门槛 | 自动化程度 | 适用场景 |
|------|-------------|--------|----------|-----------|----------|
| **A. 小程序 + 截图上传** | 用户上传聊天截图，视觉大模型直接"看懂"截图 | ✅ 完全合规 | 低（人人会截图） | 手动触发 | C 端主打形态 |
| **B. 小程序 + 聊天记录文件导入** | 合并转发→PC 导出 txt/html→`wx.chooseMessageFile` 选取上传 | ✅ 合规 | 中 | 手动触发 | 重度用户、长对话 |
| **C. 企业微信机器人 + 会话存档** | 官方会话内容存档 API，机器人常驻群内 | ✅ 合规（需知情同意、按坐席付费） | 需群主配置 | ✅ 全自动 | To B：社群运营、班级群、业主群 |
| **D. wechaty / 协议机器人** | 个人号挂机收消息 | ❌ 违反微信协议，封号风险 | — | 全自动 | 仅限自用原型验证 |

**推荐路线：A 为主、B 为辅的 C 端小程序先跑通体验与传播；C 作为后续 To B 商业化路径。D 只用于内部原型。**

## 2. 主形态设计：小程序「群忆」

### 2.1 核心流程

```
群里截图（长按多选/逐张保存）
        │
        ▼
小程序上传（支持批量、自动按截图内时间排序拼接）
        │
        ▼
多模态大模型：对话重建
  - 识别昵称与消息气泡归属
  - 恢复时间线与引用/回复关系
  - 理解截图内出现的照片、表情包的语义与语境
        │
        ├──► ① 上下文总结
        ├──► ② 群相册（图片整理）
        └──► ③ 珍贵回忆小结
```

### 2.2 三大功能模块

#### ① 上下文总结
- **今日话题 TOP3**：每个话题一段话 + 参与的人 + 结论
- **结论与待办**：接龙结果、约定的时间地点、群决议
- **@我的事项**：从截图中识别与"我"相关的消息
- **金句摘录**：有梗、有情绪价值的原话，标注发言人

#### ② 群图片整理（群相册）
- 从聊天截图中**自动抠出群友分享的照片**，与聊天气泡分离归档
- 按 **时间 / 事件** 聚类：聚餐、旅行、晒娃、宠物、表情包（单独归类）
- 每张照片由视觉模型生成一句描述（caption），**结合聊天上下文**：
  不只是"一群人在餐桌前"，而是"老张生日局，大家在等蛋糕上桌"
- 支持自然语言搜索："上次聚餐的合照"、"小王家猫的照片"
- 感知哈希（pHash）去重，同一张图多次转发只留一份

#### ③ 珍贵回忆小结（传播引爆点）
结合聊天语境 + 图片语义，自动生成可分享的回忆内容：

- **本周群回忆卡片**：一张精美长图 — 本周高光时刻、最佳照片、金句、活跃之星
- **月度群记忆册**：H5 翻页相册，照片 + AI 撰写的叙事小结（"这个月我们一起……"）
- **年度群报告**：网易云年度报告式 H5 — 群聊天数、最爱表情包、年度金句、年度合照、"群里最常出现的三个词"
- **里程碑自动识别**：生日、旅行、升学、婚礼、新成员入群等事件，生成纪念卡片
- 所有产物**一键分享回群**，卡片带小程序码 → 群友点进来生成自己的视角 → 自增长循环

### 2.3 辅助形态 B：聊天记录文件导入
- 引导页教用户：群里长按 → 多选 → 合并转发给自己 → PC 微信另存 → 微信发给自己 → 小程序内 `wx.chooseMessageFile` 选取
- 解析导出的 txt/html，获得完整长上下文，总结质量最高
- 作为"截图不够长"时的进阶入口，不做主路径

## 3. To B 形态：企业微信版（第二阶段）

目标用户：社群运营者、知识付费群主、班级群老师、业主群管理员。

- 机器人常驻企业微信群（或微信互通群），通过官方**会话内容存档 API** 合规获取消息
- 每天定时推送「今日群精华」到群内；每周生成群周报
- 群成员入群时明确告知存档与用途（法律要求）
- 商业模式：按群/按坐席订阅收费

## 4. 技术架构

```
┌─ 前端：微信小程序（Taro / uni-app 或原生）
│    上传、相册浏览、回忆卡片渲染、分享
│
├─ 后端：微信云开发（快速起步）或 Node 服务
│    任务队列（截图批量解析为异步任务）
│
├─ AI 层
│    ├─ 多模态大模型（如 Claude vision）：截图对话重建、图片语义理解、总结生成
│    ├─ pHash：图片去重
│    └─ 向量库：回忆语义检索（"上次聚餐的合照"）
│
└─ 存储：对象存储（图片）+ 数据库（结构化总结、相册元数据）
```

关键工程点：
- **多截图拼接**：按截图内时间戳 + 首尾消息重叠检测排序、去重拼接
- **异步处理**：批量截图解析耗时较长，走任务队列 + 完成后订阅消息通知用户
- **成本控制**：截图先压缩/裁剪再送模型；总结结果缓存

## 5. 合规与隐私（必须做）

1. **内容安全**：所有用户上传图片过 `imgSecCheck`，生成文本过 `msgSecCheck`（小程序审核硬性要求）
2. **隐私政策**：写明聊天内容仅用于生成总结与相册，不用于其他目的，支持一键删除全部数据
3. **昵称脱敏选项**：分享出去的回忆卡片可选择打码/化名
4. **个人信息保护法**：群聊涉及第三方个人信息，产品定位为"用户对自己可见内容的个人整理工具"，分享行为由用户主动发起
5. **不碰灰色接口**：正式产品不使用任何协议机器人/hook 方案

## 6. 迭代路线

| 阶段 | 内容 |
|------|------|
| MVP（4–6 周） | 截图上传 → 对话重建 → 话题总结 + 金句；基础分享卡片 |
| V1.1 | 群相册：照片抽取、事件聚类、AI caption、去重 |
| V1.2 | 周回忆卡片 / 月度记忆册 H5，分享回流闭环 |
